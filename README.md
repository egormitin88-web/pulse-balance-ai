# Пульс & Баланс — AI-консультант фитнес-клуба

Локальное учебное веб-приложение: React + TypeScript, FastAPI, SQLAlchemy и SQLite. Консультант отвечает через OpenAI API после того, как администратор добавит ключ в приложении. Публичный каталог, личный кабинет, память, записи и административные функции работают без ключа.

## Быстрый запуск в Windows

Откройте PowerShell в папке проекта и выполните:

```powershell
.\start.ps1
```

Скрипт создаст `backend/.venv`, установит Python-зависимости и запустит сервер на <http://127.0.0.1:8000>. Первая установка требует интернета. Нужен Python 3.11+; если он не найден автоматически, запустите `./start.ps1 -PythonExe "C:\path\to\python.exe"`. Готовая сборка React уже включена, Node.js для обычного запуска не нужен.

При первом запуске создаются `data/fitness.sqlite3`, секрет серверных сессий и демонстрационные данные. При повторном запуске база не перезаписывается. Приложение слушает только локальный адрес компьютера.

## Подключение OpenAI без передачи ключа в чат

1. Войдите администратором.
2. Откройте вкладку «Администратор» → «Подключение OpenAI».
3. Вставьте свой ключ OpenAI API и нажмите «Сохранить ключ».

Ключ уходит по запросу только на локальный FastAPI сервер. Если Windows Credential Manager доступен, он сохраняется там для текущего пользователя Windows. Если системное хранилище недоступно, приложение использует безопасный для локальной демонстрации режим: ключ остаётся только в памяти серверного процесса и после его перезапуска потребуется ввести ключ снова. Режим хранения отображается в админке. В SQLite, исходном коде и ответах API значение ключа не хранится. Поле ввода очищается после сохранения; удалить ключ можно в том же разделе. Для использования на другом компьютере ключ потребуется добавить там отдельно.

Для ответов AI серверу нужен исходящий HTTPS-доступ к `api.openai.com`. Если сеть блокирует соединение, чат сообщит об этом отдельно от ошибок ключа, баланса и доступа к модели. После перезапуска сервера проверьте в админке, остался ли ключ подключённым; ключ, хранившийся только в памяти, нужно ввести повторно.

## Как устроены память и доступ

- Краткосрочная память: сообщения текущего диалога хранятся в SQLite. В запрос к модели передаются последние 16 сообщений и краткое резюме ранней части длинного диалога.
- Долгосрочная память: отдельная таблица `memory_facts`. После каждого сообщения зарегистрированного клиента модель извлекает устойчивые предпочтения в строгом JSON; сервер проверяет допустимые категории, устраняет повторы и обновляет факты. В следующем диалоге активные факты подставляются в контекст.
- Официальные данные абонемента и записей хранятся в отдельных таблицах и не меняются от слов пользователя.
- Гостевой диалог связан с подписанным cookie и доступен 24 часа. Гости не получают персональные инструменты и долгосрочную память.
- Авторизация: подписанный `HttpOnly` cookie; роль и идентификатор клиента устанавливает сервер. Все обращения к памяти, сообщениям и записям проверяют владельца.
- Инструменты агента получают данные из SQL. Запись или отмена через чат создаёт предложение с кнопкой подтверждения; сервер повторно проверяет абонемент, лимиты, время и места.

В коде используются [Responses API и function calling](https://developers.openai.com/api/docs/guides/function-calling) для ответов и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) для извлечения памяти.

## Проверка

В папке `backend` с установленными зависимостями:

```powershell
.venv\Scripts\python.exe -m pytest -q
```

Подробные демонстрационные сценарии: [docs/verification.md](docs/verification.md). Тесты проверяют роли, изоляцию диалогов, сохранение и удаление памяти, запись на занятие, а также отсутствие ключа в ответе API. Для теста AI без вашего ключа используется имитация модели. Реальный ответ OpenAI проверяется после добавления ключа в админском разделе.

## Разработка интерфейса

Исходники React находятся в `frontend/src`. Для пересборки нужны Node.js и pnpm:

```powershell
cd frontend
pnpm install
pnpm build
```

FastAPI отдаёт готовую папку `frontend/dist`. Во время разработки можно запустить `pnpm dev` — Vite проксирует `/api` на `127.0.0.1:8000`.

## Структура и ограничения MVP

- `backend/app/models.py` — таблицы SQL; `seed.py` — тарифы, занятия и аккаунты.
- `backend/app/main.py` — REST API, роли и проверка владельца.
- `backend/app/ai.py` — промпт, инструменты агента, извлечение и резюме памяти.
- `backend/app/operations.py` — бронирование и подтверждение действий.
- `backend/app/security.py` — пароли, cookies и системное хранилище ключа.
- `frontend/src` — интерфейс клиента и администратора.

Это локальный учебный MVP. Схема базы создаётся при первом запуске через SQLAlchemy `create_all`; автоматических миграций уже существующей схемы пока нет. Перед изменением моделей сохраните копию SQLite и оформите миграцию. Оплата абонемента и реальные посещения не реализованы: администратор назначает демонстрационный абонемент вручную. Для публикации в интернете потребуются HTTPS, отдельное управление секретом сессий, полноценные миграции и удаление демо-учётных записей.
