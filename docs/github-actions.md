# Автоматические проверки GitHub Actions

Workflow: `.github/workflows/ci.yml`, название **Tests and build**.

Запускается на каждом `push` в любую ветку, а также при открытии, обновлении и повторном открытии Pull Request.

## Что выполняется

| Задание | Проверки |
|---|---|
| Frontend tests and build | Чистая установка через `npm ci`, пять тестов нового фильтра, проверка TypeScript и сборка Vite |
| Backend tests | Установка Python-зависимостей и 17 тестов API, разграничения доступа, памяти, серверного ключа и формата дат |

Задания работают независимо на GitHub-hosted Ubuntu. Используются Node.js 24 и Python 3.12. Версии официальных действий GitHub закреплены по SHA коммитов. Права workflow ограничены чтением исходного кода. API-ключ OpenAI, доступ к Vercel и адрес Neon для этих проверок не нужны: модель имитируется в тестах, а серверные тесты работают с отдельной временной SQLite.

## Где посмотреть результат

1. Открыть https://github.com/egormitin88-web/pulse-balance-ai/actions.
2. Выбрать **Tests and build** и нужный запуск.
3. Открыть одно из двух заданий, затем конкретный шаг для просмотра лога.
4. Зелёная отметка означает успех всех проверок; красная — ошибку. Пока результат неуспешен, Pull Request не следует объединять с `main`.

Те же команды можно выполнить локально:

```powershell
npm.cmd ci --prefix frontend
npm.cmd test
npm.cmd run build
```

Для серверных тестов из папки `backend`:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Намеренная ошибка с красной проверкой и последующим исправлением относится к следующему пункту ДЗ. Pull Request и объединение с `main` выполняются после этого.
