## Как устроено размещение

Один проект Vercel содержит два сервиса: React/Vite из `frontend` и FastAPI из `backend`. Настройки находятся в `vercel.json`. Запросы `/api/*` направляются в FastAPI, остальные — в интерфейс. PostgreSQL находится в существующем проекте Neon, ветка `production`, регион Frankfurt. Данные сохраняются между публикациями.

Локальное приложение читает `.env.local` и использует ту же учебную БД. Поэтому изменения учебных данных локально видны в опубликованной версии. Автоматические тесты используют отдельную временную SQLite и не изменяют эту БД.

Если сеть компьютера блокирует PostgreSQL на порту 5432, локальный сервер автоматически использует мост через защищённый WebSocket Neon. Пароли не выходят за пределы зашифрованного внешнего соединения. Мост слушает только случайный порт на `127.0.0.1`. Настройки DNS, VPN и брандмауэра Windows не изменяются. Vercel использует обычное подключение PostgreSQL. Мост реализован в `backend/app/neon_tunnel.py`; для диагностики можно установить `FITNESS_NEON_TRANSPORT=tcp` или `websocket` только локально.

Официальные описания: [сервисы Vercel](https://vercel.com/docs/services), [маршрутизация](https://vercel.com/docs/services/routing), [протокол и шифрование WebSocket Neon](https://github.com/neondatabase/serverless/blob/main/CONFIG.md).

## Закрытые настройки

В Vercel для окружения Production настроены:

| Имя | Назначение |
|---|---|
| `DATABASE_URL` | Подключение к постоянной PostgreSQL в Neon; хранится как Secret |
| `OPENAI_API_KEY` | Действующий ключ OpenAI; хранится как Secret |
| `FITNESS_SESSION_SECRET` | Постоянный случайный секрет подписи сессий; хранится как Secret |
| `FITNESS_SECURE_COOKIES=1` | Cookie авторизации передаётся только по HTTPS |

Ключ не отображается в API, не включается в собранный JavaScript и не изменяется через общедоступную демо-админку. Его обновляет владелец через настройки Vercel. После смены переменной требуется новая публикация.

Локальные секреты хранятся в игнорируемом `.env.local`. Значения не включены в этот документ. Пользователь выбрал для нового ключа срок действия **7 дней**; ориентировочная дата окончания — **17 ноября 2026 года**. Перед окончанием срока ключ потребуется обновить.

Для Preview настроены отдельный секрет сессий, ключ и `DATABASE_URL` ветки Neon `preview-schedule-availability`. Она изолирована от Production и автоматически истекает 17 ноября 2026 года. Эти настройки используются только для проверочных публикаций. Подробности — в [описании новой функции](schedule-availability.md).

## Что исправлено перед публикацией

- Даты из PostgreSQL больше не получают некорректное окончание `+00:00Z`; страницы админки открываются.
- Даты из SQLite и PostgreSQL приводятся к единому UTC-представлению, чтобы сравнения при записи, отмене и подтверждении работали одинаково.
- При отсутствии `DATABASE_URL` или постоянного секрета сессий Vercel сообщает об ошибке настройки, а не создаёт временную базу или случайные сессии.
- При запуске функции Vercel схема БД и демо-данные повторно не создаются. Они подготовлены заранее.
- Добавлены проверка `/api/health`, конфигурация публикации, исключения для секретов и воспроизводимая установка интерфейса через `npm ci`.
- Истёкший ключ OpenAI заменён через защищённую процедуру, без публикации значения.

## Учебные ограничения

Демонстрационные логины и пароли сохранены по прямому решению владельца. Приложение предназначено для вымышленных данных. Демо-администратор может изменять учебные тарифы и профили, но не получает ключ из закрытых настроек сервера. Для реальных клиентов нужны отдельные учётные записи, миграции схемы и дополнительная проверка безопасности.

Этот этап покрывает подготовку и публикацию приложения. Следующие пункты ДЗ — новая функция в отдельной Git-ветке, GitHub Actions, намеренно неуспешная проверка с исправлением и Pull Request — выполняются отдельно.
